# 커밋 메시지 생성

staged된 변경사항을 분석해서 아래 컨벤션에 맞는 커밋 메시지를 생성하고 커밋한다.

## 커밋 타입

| 타입 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 리팩토링 |
| `style` | 코드 포맷, 세미콜론 등 스타일 변경 |
| `chore` | 빌드, 패키지, 설정 변경 |
| `docs` | 문서 수정 |
| `test` | 테스트 코드 추가/수정 |

## 형식

```
<타입>: <한국어 설명>
```

예시:
- `feat: 카카오 로그인`
- `fix: 번역 API 동시 요청 방지`
- `refactor: 이메일 전송 코드 주석 처리`
- `chore: pnpm 의존성 업데이트`

## 규칙

- 설명은 **한국어**로 작성
- 마침표 없이 간결하게
- 무엇을 했는지 명확하게 (why는 PR 설명에)

## 실행 절차

1. `git status` 로 변경된 파일 목록 파악
2. `.env`, 시크릿, 민감한 파일은 제외하고 `git add` 로 관련 파일 staged
3. `git diff --staged` 로 변경사항 상세 파악
4. 변경 내용에 맞는 타입 선택
5. 한국어로 간결한 설명 작성
6. 커밋 실행
